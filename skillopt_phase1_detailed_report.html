05 · Actor 模块

每一步决策是怎样产生的？

👁️
状态读取

组合原始任务目标、当前 observation、最近轨迹和 Skill。

🔢
动作编号

给 admissible actions 编号，模型只返回整数 action_id。

🛟
非法重试

编号无效时反馈错误，最多重试 2 次；之后才启用标记回退。

🔁
停滞控制

阻止短期重复动作；8 步无进展循环时提前停止。

06 · Skill Manager 模块

从失败轨迹到候选经验

🗜️
Trajectory Compact

抽取目标、动作序列、最终观察和失败信息，控制提示长度。

🔍
Diagnosis

寻找动作重复、目标遗失、顺序错误或错误交互。

✍️
Candidate Edit

保留有效规则，只添加有轨迹证据且可复用的新规则。

⚖️
Validation Gate

候选与 incumbent 在同一 held-out validation 任务上重新运行。

07 · 完整实验流程

一次更新，七个步骤

数据用途严格分离，避免用测试集反向选择 Skill。

🎮Train执行任务
🧾Trace记录轨迹
🔍Reflect诊断失败
✍️Edit候选 Skill
⚔️A/B Valid新旧对比
🚪Gate接受/拒绝
🧪Test最终泛化
Train

只产生证据

轨迹用于反思和生成候选，不负责证明候选有效。

Valid Seen

只做更新决策

incumbent 与 candidate 接受完全相同的验证任务。

Valid Unseen

只报告最终结果

同时运行 No Skill 基线和最终 Skill，绝不参与更新。

08 · 决策可靠性

哪些设计避免“假改进”？

🔒冻结模型

隔离变量：性能差异主要来自 Skill，而不是权重变化。

same model digest
🧪独立验证

生成候选与判断候选使用不同任务用途。

train ≠ validation
🧭精确动作映射

模型只选编号，避免字符串拼写差异伪装成策略问题。

action_id → command
🧯错误显式计数

非法动作、重试和回退全部记录，不能被当成模型成功。

invalid_actions
第一阶段门控：只有 `(success_rate, mean_score)` 严格字典序提升，候选才会被接受。

10 · 结果解读与局限

证明了链路，尚未证明规模化有效

🔬

样本量为 1

100% 与 0% 都来自单任务，不能估计统计波动。

LIMIT 01
⚖️

门控忽略效率

候选从 7 步降到 3 步，却因奖励持平而被拒绝。

FINDING 01
📝

自由文本 Skill

整段 Markdown 更新，难定位具体是哪条规则带来变化。

LIMIT 02
⏱️

本地推理较慢

20 步训练约 26 分钟，扩量需要规划运行成本。

CONSTRAINT
当前最稳妥的结论：核心因果闭环可以运行；Skill 对决策有明显影响；更新门控需要适配“决策效率持续改进”的研究目标。
